# MitmProxy Simulator - Implementation Brief

**Project:** MitmProxy Simulator UI  
**Methodology:** IFD (Iterative Flow Development)  
**Version:** v0.1.0 (MVP)

---

## Purpose

A standalone QA/UX tool to test MitmProxy behavior **without needing to route traffic through the actual proxy**. Allows developers to:

1. Simulate browser requests with any `mitm-mode` cookie
2. Execute against **live** MitmProxy API endpoints
3. View request/response flow with side-by-side comparison
4. Test all transformation modes (cache, xxx, xxx-negative, hashes, etc.)

### What's Live vs Simulated

| Component | Live/Simulated | Notes |
|-----------|----------------|-------|
| MitmProxy API (`/proxy/process-request`, `/proxy/process-response`) | **LIVE** | Real API calls |
| HTML Graph API | **LIVE** | Real cache store/load |
| Cache Service | **LIVE** | Real transformation cache |
| **Upstream Server** | **SIMULATED** | Cannot call external sites (CORS) |

The upstream server response is the only simulated part - we provide sample HTML documents that represent what an upstream server would return.

## Live API Endpoints

### MitmProxy Service

**Base URL:** `https://mitmproxy-api.dev.mgraph.ai` (or relative if same-origin)

```
POST /proxy/process-request
POST /proxy/process-response
```

### HTML Graph Service

**Base URL:** `https://html-graph.dev.mgraph.ai`

```
POST /flet-html-domain/html/store/{namespace}/key/{cache_key}
POST /flet-html-domain/html/load/{namespace}/key/{cache_key}
```

## Transformation Modes (Enum__HTML__Transformation_Mode)

| Mode | Cookie Value | Behavior |
|------|--------------|----------|
| OFF | `off` | Pass through unchanged |
| **CACHE** | `cache` | HTML Graph cache (new) |
| XXX | `xxx` | Mask all text with xxx |
| XXX_RANDOM | `xxx-random` | Mask random 50% |
| XXX_NEGATIVE | `xxx-negative` | Mask negative sentiment only |
| XXX_NEGATIVE_1 | `xxx-negative-1` | Mask negative > 0.1 threshold |
| XXX_NEGATIVE_2 | `xxx-negative-2` | Mask negative > 0.2 threshold |
| XXX_NEGATIVE_4 | `xxx-negative-4` | Mask negative > 0.4 threshold |
| XXX_HIDE_POSITIVE | `xxx-hide-positive` | Mask positive sentiment |
| XXX_HIDE_NEUTRAL | `xxx-hide-neutral` | Mask neutral sentiment |
| HASHES | `hashes` | Replace text with hash IDs |
| HASHES_RANDOM | `hashes-random` | Random 50% as hashes |
| ABCDE_BY_SIZE | `abcde-by-size` | Group by text length |

### Component: `<mitmproxy-simulator>`

**Purpose:** Main orchestrator, holds state, coordinates flow execution

**State:**
```javascript
{
    url: "https://news.acme-corp.test/articles/tech-trends-2026",
    mode: "cache",
    sampleHtml: "article-page",
    stages: {
        request:  { status: "idle", input: null, output: null, timing: null },
```

**Events Emitted:**
- `flow-started` - When execution begins
- `stage-completed` - When a stage finishes
- `flow-completed` - When entire flow finishes

**Purpose:** Configuration inputs

**Events Emitted:**
- `config-changed` - When URL, mode, or sample changes
- `execute-requested` - When Execute button clicked

### Component: `<pipeline-status>`

**Purpose:** Visual pipeline with stage status boxes

**Events Listened:**
- `stage-completed` - Updates corresponding box

### Component: `<details-panel>`

**Purpose:** Tabbed view showing input/output for each stage

**Sub-components:**
- `<stage-tab>` - Individual tab content with side-by-side view

## Flow Execution Logic

### Full Flow (cache mode)

```javascript
async executeFlow() {
    const { url, mode, sampleHtml } = this.state;
    
    // 1. REQUEST PHASE
    this.updateStage('request', 'running');
    const requestInput = this.buildRequestPayload(url, mode);
    const requestStart = performance.now();
    const requestOutput = await this.callProcessRequest(requestInput);
    this.updateStage('request', 'complete', requestInput, requestOutput, performance.now() - requestStart);
    
    // 2. CACHE CHECK (for cache mode, result is in requestOutput)
    if (mode === 'cache') {
        if (requestOutput.status_code === 200 && requestOutput.headers?.['x-cache-source']) {
            // Cache HIT - flow ends here
            this.updateStage('cache', 'hit', null, requestOutput);
            return;
        } else {
            this.updateStage('cache', 'miss');
        }
    }
    
    // 3. UPSTREAM (simulated)
    this.updateStage('upstream', 'simulated');
    const upstreamResponse = SAMPLE_HTML[sampleHtml].html;
    this.updateStage('upstream', 'complete', null, { body: upstreamResponse });
    
    // 4. RESPONSE PHASE
    this.updateStage('response', 'running');
    const responseInput = this.buildResponsePayload(url, mode, upstreamResponse);
    const responseStart = performance.now();
    const responseOutput = await this.callProcessResponse(responseInput);
    this.updateStage('response', 'complete', responseInput, responseOutput, performance.now() - responseStart);
}
```

## API Client (js/api-client.js)

```javascript
const ApiClient = {
    // Base URLs - relative if same-origin, absolute if different
    mitmproxyBase: '/proxy',  // or 'https://mitmproxy-api.dev.mgraph.ai/proxy'
    htmlGraphBase: '/flet-html-domain',
    
    async processRequest(payload) {
        const response = await fetch(`${this.mitmproxyBase}/process-request`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(payload)
        });
        return response.json();
    },
    
    async processResponse(payload) {
        const response = await fetch(`${this.mitmproxyBase}/process-response`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(payload)
        });
        return response.json();
    }
};
```
